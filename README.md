# Рамка для фотографий

Оконное приложение для пакетного добавления рамок к фотографиям. Поддерживает
отдельные изображения и целые папки, показывает результат до обработки и не
перезаписывает оригиналы по умолчанию.

## Возможности

- обработка одного изображения или всех изображений в папке;
- живой предпросмотр результата;
- цвет рамки из системной палитры или в формате `#RRGGBB`;
- фоновое изображение под фотографией;
- квадратный или пропорциональный исходнику результат;
- настраиваемый размер рамки от 0 до 200%;
- сохранение JPG, JPEG, PNG и BMP с исходным именем;
- фоновая обработка нескольких файлов с индикатором прогресса.

Фоновое изображение размещается по центру без масштабирования. Большой фон
обрезается по размеру результата, а вокруг слишком маленького фона остаётся
выбранный цвет рамки.

Исходная фотография и выбранный фон защищены от перезаписи результатом.
Размеры округляются до ближайшего целого пикселя, половины — вверх.
Превью вычисляется в отдельном потоке и ограничено 1200 пикселями по большей
стороне; это ограничение не влияет на размеры сохраняемых файлов.

## Быстрый запуск

Требуются Windows и Python 3.10 или новее. В PowerShell выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

## Использование

1. Кнопкой «Выбрать папку…» укажите папку с изображениями.
2. Чтобы обработать один файл, дважды щёлкните по предпросмотру или нажмите
   `Ctrl+O`.
3. Выберите папку для готовых файлов. По умолчанию создаётся соседняя папка
   `<имя>_with_frame`.
4. Задайте процент, цвет, необязательный фон и режим «Оквадратить».
5. Нажмите «Добавить рамку» или `Ctrl+Enter`.

При выборе папки вложенные каталоги не обходятся. В предпросмотре показывается
первое поддерживаемое изображение в алфавитном порядке.

## Тесты

```powershell
python -m unittest discover -s tests -v
```

GitHub Actions запускает тесты на Python 3.10, 3.11 и 3.12 при push в ветку и
pull request. Сборка по тегу или ручному запуску сначала выполняет те же тесты
на всех трёх версиях Python и продолжается только при их успехе.

## Сборка Windows EXE

```powershell
python -m pip install -r requirements-build.txt
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Однофайловая сборка без консольного окна появится в
`dist\AddingFrameToPhotos.exe`. Каталоги `build` и `dist` намеренно не входят в
Git: готовый EXE следует прикреплять к GitHub Release.

Workflow **Build Windows EXE** также можно запустить вручную на вкладке Actions.
Он автоматически запускается для тегов вида `v1.0.0` и сохраняет EXE как
артефакт сборки.

## Структура проекта

```text
.
├── assets/                         # иконка и её исходник
├── photo_frame_app/
│   ├── image_processor.py          # поиск и обработка изображений
│   ├── models.py                   # параметры и результаты обработки
│   ├── preview_worker.py           # фоновое вычисление актуального превью
│   └── ui/
│       ├── controls.py             # элементы управления
│       ├── main_window.py          # главное окно и координация
│       └── preview.py              # панель предпросмотра
├── tests/                          # модульные тесты
├── build.ps1                       # сборка PyInstaller
├── main.py                         # точка входа
├── requirements.txt                # зависимости приложения
└── requirements-build.txt          # зависимости сборки
```

Логика обработки отделена от интерфейса, поэтому её можно использовать без GUI
через `ImageProcessor` или совместимую функцию `process_folder` из `main.py`.
Функции `process_folder` и `add_white_border_to_square` принимают долю: `0.16`
означает 16%. В интерфейсе и `FrameSettings.percentage` используются проценты: `16`.

## Публикация версии

1. Убедитесь, что тесты проходят и рабочее дерево чистое.
2. Создайте тег, например `v1.0.0`, и отправьте его на GitHub.
3. Дождитесь workflow **Build Windows EXE**.
4. Создайте Release для тега и приложите полученный EXE-артефакт.

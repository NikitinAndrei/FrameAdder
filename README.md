# Рамка для фотографий

Небольшое Windows-приложение для добавления рамки к одной фотографии или всем
изображениям в папке. Перед обработкой оно показывает превью и сохраняет
готовые файлы отдельно от оригиналов.

## Возможности

- JPG, JPEG, PNG и BMP как источник и результат;
- выбор папки с фотографиями или одного изображения;
- предпросмотр первой фотографии из папки;
- цвет рамки из системной палитры или в строгом формате `#RRGGBB`;
- размер рамки от 0 до 200 %;
- квадратный результат или рамка с сохранением пропорций исходника;
- необязательное фоновое изображение;
- обработка в фоновом потоке с индикатором прогресса.

При включённом режиме «Оквадратить» сторона результата рассчитывается от
большей стороны изображения. Если режим выключить, ширина и высота
увеличиваются на заданный процент по отдельности. Размеры округляются до
ближайшего пикселя; значение `0.5` округляется вверх.

Фон и исходная фотография центрируются без масштабирования. Большой фон
обрезается по границам результата, а вокруг маленького остаётся цвет рамки.
Программа не позволит записать результат поверх исходного или фонового файла.

Превью вычисляется в отдельном потоке и имеет максимум 1200 пикселей по
большей стороне. Это ограничение действует только на превью, а не на
сохраняемые фотографии.

## Запуск из исходников

Нужны Windows и Python 3.10 или новее. В PowerShell из папки проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Если команда `py -3.12` недоступна, используйте установленную версию Python
3.10 или новее вместо неё.

## Использование

1. Нажмите «Выбрать папку…», чтобы обработать все изображения из папки.
   Вложенные папки не обходятся.
2. Для одного файла дважды щёлкните по области превью или нажмите `Ctrl+O`.
3. Укажите папку для готовых файлов. По умолчанию это соседняя папка вида
   `<имя>_with_frame`.
4. Настройте процент, режим результата, цвет и при необходимости фон.
5. Нажмите «Добавить рамку» или `Ctrl+Enter`.

Для папки в превью используется первое поддерживаемое изображение в
алфавитном порядке. Готовые файлы получают исходные имена и расширения.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

GitHub Actions запускает эти тесты на Windows с Python 3.10, 3.11 и 3.12 при
push в ветку и при pull request. Сборка EXE по тегу или вручную начинается
только после успешного прохождения этой матрицы тестов.

## Сборка EXE

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Готовый файл появится в `dist\AddingFrameToPhotos.exe`. Скрипт также может
создать служебные `build\` и `AddingFrameToPhotos.spec`; они намеренно
игнорируются Git. EXE прикрепляйте к GitHub Release, а не добавляйте в репозиторий.

Workflow **Build Windows EXE** доступен на вкладке Actions и автоматически
запускается для тегов формата `v*`, например `v1.0.0`. Собранный EXE можно
забрать из артефактов workflow.

## Публикация версии

После того как изменения отправлены в GitHub:

```powershell
git tag -a v1.0.0 -m "v1.0.0"
git push origin v1.0.0
```

Дождитесь workflow **Build Windows EXE**, затем создайте GitHub Release для
тега и приложите скачанный EXE.
